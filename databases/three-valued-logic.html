01 · the logic

TRUE, FALSE and UNKNOWN

SQL uses NULL for a value that is missing. Any comparison with a missing value cannot be decided, so its result is the third truth value, UNKNOWN. Read UNKNOWN as “TRUE or FALSE, we just don't know which”: an operator gives a definite answer only when both possibilities lead to the same result.

Who keeps a row?

WHERE · ON · HAVING

A row survives only if the condition is TRUE. UNKNOWN is treated like FALSE.

CASE WHEN … THEN

A branch fires only if its condition is TRUE; UNKNOWN falls through to the next WHEN or the ELSE.

CHECK constraint

A row is rejected only if the condition is FALSE. UNKNOWN passes, so a CHECK alone does not keep NULLs out.
